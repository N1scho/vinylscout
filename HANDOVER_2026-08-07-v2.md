## Issues Fixed & Resolution

### Issue 1: Discover Items Disappear on Reload

**Root Cause:** `allAlbums` not persisted in localStorage. When user reloaded page from Wishlist tab, store had empty `allAlbums`, blocking wishlist items from displaying.

**Fix:** Added app-mount initialization in App.jsx:
```javascript
useEffect(() => {
  const discover = useDiscoverStore.getState();
  if (discover.allAlbums.length === 0) {
    discover.initializeAlbums(discoverData);
  }
}, []);
```

**Result:** 79 albums load on app start, available to all views immediately.

---

### Issue 2: Wishlist Missing Price Display & Refresh Button

**Root Cause:** WishlistView had no price fetching or display; users couldn't see prices or update them.

**Fix:**
- Added `fetchPriceInfo` call on component mount
- Display price in card layout (USD/EUR + value)
- Add RotateCcw refresh button at top-left (blue circle)
- Graceful error handling for unavailable prices

**Layout Changes:**
- Refresh button: top-left (blue), matches heart button at top-right (red)
- Price moved up: appears after artist, before year
- Fallback: shows "—" if no price available (covers API errors, no listings)

**Result:** Wishlist items show prices with refresh capability, same UX as Discover.

---

### Issue 3: Infinite Loop / Flickering

**Root Cause:** DiscoverView effect had `initializeAlbums` function in dependency array. Zustand store functions are recreated each render, causing effect to re-run every render, triggering constant re-initialization.

**Fix:** Removed function from dependencies—effect now depends only on data values:
```javascript
useEffect(() => {
  if (allAlbums.length === 0 || (allAlbums.length > 0 && selectedGenreIds.length === 0 && !userClearedGenres)) {
    initializeAlbums(discoverData);
  }
}, [allAlbums.length, selectedGenreIds.length, userClearedGenres]); // removed initializeAlbums
```

**Result:** No flickering, stable renders.

---

### Issue 4: Price Fetch Errors ("endpoint not allowed")

**Root Cause:** Wishlist tries to fetch prices from `/api/discogs-proxy` (Vercel serverless function). In local dev, endpoint doesn't exist; API calls fail.

**Fix:** Improved error handling:
- Catch fetch errors silently
- Mark item as tried (cache = null) to prevent retry spam
- Show "—" instead of error message
- Refresh button always available for manual retry
- Works seamlessly on Vercel (prices fetch), local dev (shows "—")

**Result:** No crashes, graceful degradation, clean UX.

## Architecture Notes

### Store Persistence

`discoverStore` persists to localStorage:
- `wishlist` — array of album IDs
- `selectedGenreIds` — filter selection
- `yearRange`, `priceRange` — slider positions
- `currentAlbumIndex` — gallery position

**Not persisted:** `allAlbums`, `genres` (too large for localStorage, reloaded from bundle on app mount)

### Price Fetching Flow

1. **WishlistView mounts** → checks priceCache
2. **For each uncached item** → calls `fetchPriceInfo(id)`
3. **fetchPriceInfo** → POST to `/api/discogs-proxy` with releaseId
4. **Vercel function** (prod only) → authenticates with DISCOGS_TOKEN, queries `/marketplace/stats/{id}`
5. **Response** → `{ value, currency }` or error
6. **Error handling** → mark as tried, show "—", allow retry via refresh button
